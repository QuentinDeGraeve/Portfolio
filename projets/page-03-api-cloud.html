Le problème

Une API exploitable ne se limite pas à répondre à une requête. Elle doit être testable (on peut vérifier ce qu'elle fait), sécurisée (elle rejette ce qu'elle ne devrait pas accepter), observable (on sait ce qui se passe en production) et déployable de manière reproductible (pas de "ça marchait sur ma machine").

Ce projet construit cette API pas à pas, avec une décision documentée à chaque étape.

Structure du code

L'architecture suit un découpage en couches classiques (controller, service, repository) mais avec une attention explicite aux contrats entre couches :

  • Validation à l'entrée — Bean Validation sur les DTO, pas de confiance implicite sur les données reçues
  • Séparation domaine / infrastructure — le cœur métier ne dépend pas du framework
  • Gestion des erreurs — codes HTTP cohérents, messages d'erreur non verbeux côté client

Tests & sécurité

La stratégie de test sera documentée avec les taux de couverture réels :

  • Tests unitaires sur la logique métier
  • Tests d'intégration avec base de données de test (H2 ou Testcontainers)
  • Tests de contrat sur les endpoints REST

La sécurité couvre : authentification JWT, validation des permissions, protection contre les injections SQL et limitation de débit.

Conteneur & pipeline CI

Le Dockerfile sera optimisé (multi-stage build, image de base minimale, utilisateur non-root). Le pipeline CI — sur GitHub Actions — exécute dans l'ordre : compilation, tests, analyse statique, build image, publication vers le registry.

Chaque étape est une porte : si les tests échouent, l'image n'est pas construite.

Déploiement AWS

L'infrastructure est décrite en code avec Terraform. La cible est ECS Fargate : pas de serveur à gérer, scaling automatique, logs centralisés dans CloudWatch.

  • VPC avec subnets publics / privés
  • ALB (Application Load Balancer) devant les conteneurs
  • RDS PostgreSQL en subnet privé
  • Secrets Manager pour les variables sensibles

Limites

Cette fiche est une architecture de démonstration — le dépôt et l'environnement déployé seront indiqués quand ils seront disponibles. Les coûts AWS réels seront documentés.
